RUNTIME PHYSICS

Simulate physical entities using a 60Hz fixed-timestep scheduler paired with change-driven grid updates.

CORE CONCEPT

AeoEngine isolates simulation data cleanly from authored files. When entering Play mode, anchored solid voxels populate the rigid collision map, while free cell objects initialize as dynamic PhysicsBodies. This structure guarantees that real-time shifts do not damage permanent authored scene maps. For programmatic control, see Runtime Overrides.

WORKFLOW / ARCHITECTURE

DATA PIPELINE

During simulation, dynamic bodies process velocity and support calculations. Inexpensive cell tracking bounds system overhead. The pipeline cascades as follows:

CONVERSION PIPELINE 
Data Conversion Pipeline:
Authored World Data (Authoritative Baseline)
      │
      ▼
Runtime Conversion Pipeline
      │
      ├──► PhysicsWorld (Static Voxel Grid Layout)
      └──► Dynamic PhysicsBodies (60Hz Motion Loops)

EXPLANATION: To prevent continuous overhead across static assets, updates are change-driven. Modifying a block's parameters marks that index as dirty, allowing the scheduler to reconcile only the elements that shifted.

COMMON NOTES / LIMITATIONS

Support Tracking: Stacked dynamic blocks perform support checks, transitioning into specialized sleeping states when physical contact stabilizes.

Narrow-Phase Detection: Pairwise body checks bound dynamic interactions; uniform spatial grids and spatial hashing are planned architectural expansions.

Tunneling Boundaries: The physics model employs discrete testing loops; continuous collision volume detection is scheduled where extreme velocities require it.
