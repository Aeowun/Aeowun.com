PROJECT MANAGEMENT

Initialize and manage standalone AeoEngine persistent project workspaces and asset directories.

AEOENGINE // FUNDAMENTALS

OVERVIEW

WHAT YOU'LL LEARN

  • — Managing project environments from the Home screen
  • — Persistent world data and project structures
  • — Automated local asset pipeline setup
  • — Importing PNG textures into asset pools

CORE CONCEPT

AeoEngine maintains a strict separation between persistent authored world configurations and simulation state. Project structures bundle .world maps along with a dedicated, isolated .assets/textures/ asset directory to ensure that scene files and resources remain cohesive across workspace restarts.

WORKFLOW / ANATOMY

DIRECTORY LAYOUT

Projects are managed locally. Creating or loading a project from the Home screen anchors the editor workspace. The directory layout maps out as follows:

DIRECTORY STRUCTURE PROJECT 
Project Directory Layout:
├── MyProject.world             # Authored voxel and entity layout configuration
└── .assets/
    └── textures/               # Project-owned texture files
        ├── wall_brick.png      # Imported asset
        └── floor_stone.png     # Imported asset

EXPLANATION: When a texture file is selected via the editor Texture controls, the asset pipeline automatically creates the local directory if missing, copies the target file, assigns a unique texture identifier, and updates the renderer's real-time texture cache.

COMMON NOTES / LIMITATIONS

Persistence Boundaries: Authored data survives restarts, whereas interactive adjustments done during runtime simulation are strictly temporary.

Asset Formatting: The project texture importer enforces explicit PNG file filtering.

Renderer Fallbacks: If an assigned texture asset goes missing, the dynamic renderer handles the exception gracefully using a fallback color texture placeholder.
