CHARACTER RUNTIME

Spawn, track, and animate custom 3D character controllers inside the simulation workspace.

AEOENGINE // FUNDAMENTALS

OVERVIEW

WHAT YOU'LL LEARN

  • — Validating grid environments via authored SpawnPoint cells
  • — Configuring 60Hz fixed-timestep locomotion and vectors
  • — Resolving complex floor, wall, and ceiling voxel boundaries
  • — Blending isolated 3D skeleton clip animation values

CORE CONCEPT

The gameplay locomotion matrix is governed by a dedicated CharacterSystem module. Spawning triggers directly off authored grid points, running clearance scans before placement. The module handles movement physics, collision boundaries, and rig skeleton clip state interpolation independently of the renderer.

WORKFLOW / LOCOMOTION

VECTOR MATRIX

Locomotion blends states seamlessly. Kinematic updates handle grid collisions and orientation vectors smoothly. Key attributes include:

CHARACTER VECTOR MATRIX 
Character Vector Matrix:
- Idle State: Evaluated mesh stance activated when horizontal velocity hits zero.
- Walk State: Locomotive skeletal clip cycling proportional to active movement speed.
- Grounded Gate: Input filtering blocking jump executions unless floor contact is true.
- Rig Orientation: Character orientation tracks movement vectors independently of view angles.

EXPLANATION: Moving entities query voxel data to resolve three-axis collisions. Poses pass down into a dynamic geometry assembler that populates customized meshes frame by frame.

COMMON NOTES / LIMITATIONS

Clearance Scans: SpawnPoint validation scans adjacent voxel indices to confirm that spawning characters will not start stuck inside geometry.

Collision Bounds: Character collision boundaries use strict absolute scales, remaining unaffected by changes made to visual mesh configurations.

Timestep Locks: Skeletal animations and physics resolution execute exactly inside the continuous 60Hz simulation ticking structure.
