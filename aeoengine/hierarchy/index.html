HIERARCHY & SELECTION

Organize authored scenes using grouped cell hierarchies and manage multi-object cell selections.

AEOENGINE // FUNDAMENTALS

OVERVIEW

WHAT YOU'LL LEARN

  • — Navigating coordinate-based entries in the Hierarchy panel
  • — Utilizing viewport drag-selection bounding maps
  • — Inspecting shared properties for multi-cell blocks
  • — Tracking active persistent cell selection outlines

CORE CONCEPT

The World Hierarchy structural graph indexes objects chronologically and spatially by cell type and absolute grid coordinate. Integrating the hierarchy view with viewport drag multi-selection enables swift manipulation of layout profiles across massive voxel architectures.

WORKFLOW / ANATOMY

HIERARCHY GRAPH

Authored cells are grouped by type in the tree structure. Multi-cell selection updates parameters across the targeted collection instantly. The data topology outlines as follows:

WORLD HIERARCHY GRAPH 
World Hierarchy Overview:
├── Blocks                  # Collection of authored layout blocks
│   ├── Block [0, 0, 0]     # Node indexed by grid coordinate
│   └── Block [1, 0, 0]     # Node indexed by grid coordinate
└── Lights                  # Collection of authored light cells
    └── Light [2, 1, 2]     # Emissive entity definition node

EXPLANATION: Tapping elements inside the tree focuses inspectors on specific instances. Viewport drag bounding boxes let you grab collections at once, generating unified outline indicators over all included meshes.

COMMON NOTES / LIMITATIONS

Scalability Constraints: Storing cells individually requires active collection traversal. Spatial grid chunking is listed under active performance blueprints.

Scripting Binding Interop: AeoScript hooks onto unique, stable numeric Cell IDs. Human-facing names (entity identities) may be shared across multiple elements without conflicting.

Properties Scope: Batch editing fields inside the inspector applies property assignments to every active cell in the selection list.
