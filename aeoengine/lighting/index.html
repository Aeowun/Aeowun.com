LIGHTING SYSTEMS

Configure authored Light cells and simulate precise directional and point lighting environments.

AEOENGINE // FUNDAMENTALS

CORE CONCEPT

Lighting in AeoEngine treats illumination elements as native authored scene data rather than purely runtime or transient effects. Light cells occupy dedicated grid nodes, allowing authors to save emissive properties directly inside world databases to maintain illumination consistency between editing and simulation cycles.

WORKFLOW / DATA TYPE

SPECIALIZATION

Light nodes are placed inside the environment using dedicated build options. During editor placement, the system generates custom preview identifiers. The cell attributes distinguish as follows:

AUTHORED CELL SPECIALIZATION 
Authored Cell Specialization:
- Solid Block Cell: Employs physics geometry collision boundaries and texture mapping.
- Emissive Light Cell: Emits point/directional lighting streams; excluded from collision passes.
- Ghost Preview: Displays dedicated wireframe indicators showing illumination bounds.

EXPLANATION: Since lights reside as formal grid components, they save seamlessly into world persistence arrays. Furthermore, light attributes can be adjusted dynamically during live gameplay via AeoScript property overrides.

COMMON NOTES / LIMITATIONS

Physics Filtering: The physics system automatically bypasses Light cells to prevent dynamic objects from colliding with light sources.

Persistence Models: Light cell definitions, positions, and active color parameters share the identical serialization pipeline utilized by architectural blocks.

Runtime Overrides: Scripts can mutate active light colors or visibility parameters mid-simulation without corrupting authored baselines.
