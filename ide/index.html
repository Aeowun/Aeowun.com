AEOWUN / VS CODE FORK / MAGY DEVELOPMENT

AEOWUN IDE

This is a VS Code fork that I'm using as the place to build and test MAGY inside a real development environment. The editor, terminal, filesystem, project model, and MAGY can work together instead of living in separate windows.

ACTIVE DEVELOPMENT
VS CODE / MONACO / XTERM MAGY / RUST / PYTHON
WHY A FORK?

START WITH SOMETHING THAT ALREADY WORKS.

VS Code already solves a lot of the boring parts of building an editor: source editing, tabs, extensions, search, terminals, settings, keyboard commands, and a huge amount of desktop behavior.

So instead of rebuilding an editor from scratch, AEOWUN starts from VS Code and works from there. The interesting part for me is what happens when MAGY and project-level understanding are brought into that environment.

VS CODE BASE

The editor starts from the VS Code codebase rather than attempting to recreate an IDE from scratch.

MAGY INTEGRATION

MAGY is being brought into the IDE rather than treated as a completely separate application.

PROJECT CONTEXT

Project files, structure, analysis, and editor context can be considered together.

KEEP WHAT WORKS

Existing editor capabilities don't need to be reinvented just because the project is being changed underneath them.

WORKSPACE

PUT THE TOOLS WHERE THE WORK IS.

The work here is also exploring how the IDE workspace itself should behave. Panels, tabs, terminals, project views, and other surfaces can be opened and rearranged instead of requiring every tool to stay visible all the time.

DYNAMIC PANELS

Open tools when they're useful and get them out of the way when they're not.

DYNAMIC TABS

Editors and terminal sessions can share the same workspace without being locked into one layout.

RESIZABLE REGIONS

Panel boundaries can be adjusted to give the current task more or less room.

PERSISTENT STATE

Workspace, editor, project, and window state can survive a restart.

COMMAND SYSTEM

Commands are registered centrally and exposed through menus and keyboard shortcuts.

LAYERED WORKSPACE

Different project surfaces can be used together without forcing everything into one permanent view.

PROJECT MODEL

CODEGRAPH

CodeGraph represents the project as a typed property multigraph connecting physical files, symbols, occurrences, architecture, and relationships.

``` 
Project
│
├── Region
│   └── Subsystem
│       └── Component
│           └── File
│               └── Symbol
│                   └── Occurrence
│
├── Contains
├── Defines
├── Calls
├── References
├── Imports
├── Inherits / Implements
├── Type-Uses
├── Architecturally-Related
└── Semantically-Related
```
