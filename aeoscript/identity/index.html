IDENTITY vs ID

Understanding the difference between human-readable names and persistent engine identifiers.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Distinguishing between id and name
  • — Stability of persistent Cell IDs
  • — Ambiguity of non-unique authored identities
  • — Targeting specific instances for script bindings

CORE CONCEPT

AeoEngine separates an object's Human-Readable Identity (Name) from its Unique Persistent ID. While names are used for flexible gameplay discovery, the numeric ID is the absolute authority for a specific authored Cell instance. Script bindings always target the Cell ID to ensure logic remains attached to the correct object even if it is renamed or moved.

SYNTAX / WORKFLOW

EXAMPLES

STATE & BINDINGS WORKFLOW 
// Authored World State
Block ID: 18374291 Identity: Wall
Block ID: 62918403 Identity: Wall

// AeoScript Binding
Binding: ID 18374291 -> door.aeo
INSTANCE CHECK EXAMPLE 
const my_cell: Cell = ...

if my_cell.name == "Wall" {
  debug.log("I am a wall.")
}

if my_cell.id == 18374291 {
  debug.log("I am the specific wall instance 18374291.")
}

EXPLANATION: Multiple Cells can share the name "Wall". Using my_cell.name matches all of them. Using my_cell.id targets only the one specific authored instance.

COMMON NOTES / LIMITATIONS

Cell IDs are read-only and managed by AeoEngine.

Renaming a Cell in the editor updates its name but preserves its id.

Script bindings target the id so that logic doesn't break when a level designer reorganizes the world hierarchy.
