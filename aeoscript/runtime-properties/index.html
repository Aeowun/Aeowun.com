RUNTIME OVERRIDES

Modifying World objects during Play mode without affecting authored source data.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Understanding the "Runtime Override" model
  • — Modifying visible, solid, and anchored properties
  • — Overriding Cell attributes dynamically
  • — Restoring authored state by clearing overrides

CORE CONCEPT

AeoScript operates on a Runtime Override model. When a script modifies a property of a Cell, the engine creates a temporary override that exists only for the duration of the current Play session. This ensures that gameplay logic can freely manipulate the world without risk of corrupting the underlying authored World data.

SYNTAX / WORKFLOW

EXAMPLES

PROPERTY OVERRIDES SYNTAX 
cell.visible = false // Temporary runtime change
cell.attributes["health"] = 50 // Attribute override
cell.attributes["health"] = nil // Restore authored value
STATE MODIFICATION EXAMPLE 
fn hide_object(target: Cell) {
  target.visible = false
  target.solid = false
  target.anchored = true
}

fn damage(target: Cell, amount: number) {
  const current = target.attributes["hp"]
  target.attributes["hp"] = current - amount
}

EXPLANATION: Changes to visible or attributes create temporary runtime overrides. When Play mode ends, these overrides are discarded, and the authored World remains in its original state.

COMMON NOTES / LIMITATIONS

Effective property reads return the override value if it exists, otherwise the authored baseline.

Assigning nil to an attribute override removes it entirely.

Runtime overrides are not persisted to disk; use them for gameplay feedback and temporary state changes.
