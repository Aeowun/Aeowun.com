CELL HANDLES

Referencing and interacting with authored World objects through engine handles.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Understanding Cell handles as engine references
  • — Accessing persistent Cell IDs
  • — Inspecting authored Cell metadata
  • — Interacting with World objects safely

CORE CONCEPT

A Cell handle is an opaque reference to an authored World object, such as a Block or Light. Handles allow scripts to interact with engine-managed memory without directly owning it. This ensures that object lifetime and memory safety remain the responsibility of AeoEngine.

SYNTAX / WORKFLOW

EXAMPLES

HANDLE PROPERTIES SYNTAX 
handle.id // Persistent numeric ID
handle.name // Authored identity name
handle.cellType // "Block", "Light", etc.
CELL ACCESS EXAMPLE 
const target: Cell = ...

debug.log("Target Name:", target.name)
debug.log("Target ID:", target.id)

if target.cellType == "Light" {
  target.visible = false
}

EXPLANATION: Cell handles provide read-only access to authored metadata like id and name, and read/write access to runtime properties like visible for supported types.

COMMON NOTES / LIMITATIONS

Cell IDs are persistent and survive renames or movement.

Handles may become stale if the underlying object is destroyed.

Modifying a Cell through a handle creates a runtime override; it does not change the authored World file.
