EVENTS & LIFECYCLE

Responding to engine signals and hook into the standard gameplay lifecycle.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Handling engine lifecycle hooks (on_ready, update)
  • — Registering custom event handlers with on
  • — Working with delta time in update(dt)
  • — Lifecycle state persistence

CORE CONCEPT

AeoScript integrates deeply with the AeoEngine lifecycle. Scripts can respond to per-frame updates (update), initialization signals (on_ready), and specific gameplay events dispatched by the engine. This allows for reactive logic that stays synchronized with the world state.

SYNTAX / WORKFLOW

EXAMPLES

EVENT HANDLERS SYNTAX 
fn on_ready() { ... }
fn update(dt: number) { ... }
on EventName(params) { ... }
UPDATE HOOK EXAMPLE 
on PlayerSpawned(player: Entity) {
  debug.log("A new player has arrived!")
}

fn update(dt) {
  rotation += 90 * dt
  cell.offset = [0, math.sin(time), 0]
}

EXPLANATION: This script uses an event handler to log player arrivals and the update hook to apply a continuous rotation and bobbing effect using frame delta time (dt).

COMMON NOTES / LIMITATIONS

update(dt) receives the elapsed time since the last frame in seconds.

Event registrations happen when the script is loaded.

Lifecycle state persists between executions, allowing script fields to be modified and observed across frames.
