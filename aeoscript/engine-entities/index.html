ENTITY HANDLES

Interacting with live runtime objects like Players and NPCs.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Understanding Entity handles vs Cell handles
  • — Accessing runtime-only object state
  • — Querying live Entity positions
  • — Managing runtime object references

CORE CONCEPT

An Entity handle refers to a live runtime object, such as a Player or NPC. Unlike Cell handles, which represent authored World data, Entity handles represent objects that exist primarily within the running simulation. They provide a bridge to the engine's dynamic character and physics systems.

SYNTAX / WORKFLOW

EXAMPLES

RUNTIME PROPERTIES SYNTAX 
entity.id // Unique runtime ID
entity.name // Assigned runtime name
entity.position // Current world position [x, y, z]
PLAYER SPAWN EXAMPLE 
on PlayerSpawned(player: Entity) {
  debug.log("New Player:", player.name)
  debug.log("Spawn Position:", player.position)

  if player.name == "Ghost" {
    // Special logic for specific player
  }
}

EXPLANATION: When a player spawns, the engine provides an Entity handle. This handle allows the script to read the player's name and current world position for gameplay logic.

COMMON NOTES / LIMITATIONS

Entity IDs are generated at runtime and are not persistent across sessions.

Entity handles are opaque; you cannot directly access character physics or AI state unless exposed via the API.

Always check for validity if storing a reference to an Entity, as it may be destroyed (e.g., player disconnects).
