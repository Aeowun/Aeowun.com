CORE CONCEPT

The AeoScript workflow is split between the integrated code editor and the object-level binding controls in the AeoEngine editor. This dual-environment approach allows you to author scripts in a powerful Monaco-based editor while simultaneously managing how those scripts are attached to specific instances in your World.

SYNTAX / WORKFLOW

EXAMPLES

AUTHORING STEPS WORKFLOW 
1. Create .aeo file in the Workspace
2. Select World Cell -> Properties Panel
3. Attach .aeo script to Cell
4. Run Play mode -> View logs in PRINT OUTPUT
GUARD INITIALIZATION EXAMPLE 
// Workflow Example
entity Guard {
  fn on_ready() {
    debug.log("Guard initialized.")
  }
}

EXPLANATION: Scripts are authored in the Workspace. To activate them, you must bind them to a Cell in the editor. Once bound, the engine automatically handles the lifecycle and routes diagnostics to the output panel.

COMMON NOTES / LIMITATIONS

The Script Workspace provides syntax highlighting and parsing diagnostics for .aeo files.

Script bindings belong to the authored World metadata and must be saved with the level.

Use the **Script Enabled** checkbox in the Inspector to temporarily deactivate a script's top-level and lifecycle code without removing its binding.

The PRINT OUTPUT panel is your primary tool for runtime debugging and performance monitoring.
