SCRIPT CONTROL & TESTING

Turn scripts on and off dynamically during play and write automated in-game test suites.

AEOSCRIPT // MANAGEMENT

OVERVIEW

WHAT YOU'LL LEARN

  • — Enabling scripts at runtime with script.enable("scripts/trap.aeo")
  • — Disabling scripts with script.disable(path)
  • — Checking script status with script.is_enabled(path)
  • — In-game testing helpers: test.complete, test.passed, test.summary

CORE CONCEPT

AeoEngine gives scripts runtime control over which other scripts are active. You can turn enemy AI on or off, enable puzzle mechanisms after a key is collected, or temporarily disable global events. Additionally, developer test scripts can report automated test outcomes using the test namespace.

SYNTAX / WORKFLOW

EXAMPLES

SCRIPT CONTROL SYNTAX 
script.enable("scripts/boss_ai.aeo")
script.disable("scripts/trap.aeo")

if script.is_enabled("scripts/boss_ai.aeo") {
  debug.log("Boss AI is active!")
}
IN-GAME TESTING EXAMPLE 
// Automated testing script helper
test.complete("door_test", true)

if test.passed("door_test") {
  debug.log("Door test passed!")
}

debug.log("Test Summary: ", test.summary())

EXPLANATION: Disabling a script prevents its lifecycle methods (`update`, `on_touch`) from running until re-enabled. The `test` helpers are used for in-engine automated testing suites.

API SUMMARY

script.enable(path): Enables the specified script file.

script.disable(path): Disables the specified script file.

script.is_enabled(path): Checks if a script path is currently active.

test.complete(name, success) / test.summary(): Integration test assertions.
