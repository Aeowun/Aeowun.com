DIAGNOSTICS

Monitoring and debugging script execution through structured engine output.

AEOSCRIPT // ENGINE

OVERVIEW

WHAT YOU'LL LEARN

  • — Using debug.log() for structured output
  • — Interpreting runtime errors and stack traces
  • — Identifying script warnings and budget exhaustion
  • — Navigating the PRINT OUTPUT panel in the editor

CORE CONCEPT

AeoScript features a robust diagnostic system integrated directly into AeoEngine. It provides structured feedback on script execution, from simple logs to complex runtime errors. Every diagnostic message includes vital context, such as the script path, entity ID, and active function, making it easy to track down logic issues during development.

SYNTAX / WORKFLOW

EXAMPLES

DEBUG LOGGING SYNTAX 
debug.log("Message", val1, val2) // Structured logging
// View results in the Editor's PRINT OUTPUT panel
HEALTH CHECK EXAMPLE 
fn check_health(h: number) {
  debug.log("Checking health:", h)
  if h < 0 {
    debug.log("Warning: Negative health detected!")
  }
}

EXPLANATION: debug.log sends messages to the engine's output system. If a runtime error occurs (e.g., accessing a nil handle), the engine automatically prints a detailed diagnostic record including the exact source location.

COMMON NOTES / LIMITATIONS

Runtime errors terminate the active fiber immediately.

The engine enforces an execution budget to prevent runaway loops; exceeding this budget produces a specific diagnostic error.

Binding warnings help identify scripts that are incorrectly attached or entity names that do not match the World data.
