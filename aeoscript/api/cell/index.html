CELL HANDLE

Reference interface for authored World Cells.

AEOSCRIPT // API

OVERVIEW

A Cell handle refers to an authored World Cell, such as a Block, Light, or Trigger. Property modifications made to a Cell handle during Play mode are treated as runtime overrides; they do not modify the persistent authored World data.

CELL PROPERTIES

SPECIFICATION

Property Type Access Description
.id number Read-only Persistent numeric ID of the authored Cell.
.name string Read-only Human-readable authored identity. Not unique.
.cellType string Read-only The class name of the Cell (e.g., "Block").
.visible bool Read/Write Controls whether the Cell is rendered.
.solid bool Read/Write Controls collision participation.
.anchored bool Read/Write Static vs dynamic physics state.
.color basket Read/Write RGB color array [r, g, b].
.offset basket Read/Write Visual offset [x, y, z] from authored position.
.position basket Read-only Effective runtime world position [x, y, z].
USAGE

EXAMPLE

CELL PROPERTIES EXAMPLE 
const door = find("MainDoor")[0]

if door {
  door.visible = false
  door.solid = false
  debug.log("Door opened: ", door.id)
}

NOTE: Property assignments like visible = false are runtime overrides. The authored state remains unchanged once Play mode ends.

BEHAVIOR / NOTES

Reference Stability: Cell handles remain valid for the duration of the Play session. However, if an engine API explicitly destroys an authored object, the handle becomes stale.

Authored vs Runtime: Always use the unique .id for logic that must target a specific instance, as .name is not guaranteed to be unique across the World.
