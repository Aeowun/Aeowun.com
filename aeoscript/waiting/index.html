FIBERS & WAITING

Suspending execution to handle timing and asynchronous gameplay flows.

AEOSCRIPT // ASYNC

OVERVIEW

WHAT YOU'LL LEARN

  • — Understanding cooperative script fibers
  • — Suspending execution with wait(seconds)
  • — Automatic preservation of local state
  • — Yielding from nested function calls

CORE CONCEPT

AeoScript uses cooperative fibers for non-blocking asynchronous execution. The wait(seconds) operation allows a script to pause for a specific duration. When the wait is over, the fiber resumes exactly where it left off, with the entire call stack, all local variables, and loop states perfectly intact.

SYNTAX / WORKFLOW

EXAMPLES

WAIT SYNTAX ASYNC 
wait(0.5) // Pause for half a second
wait(duration) // Pause for a dynamic duration
PATROL & FLASHING EXAMPLE 
fn flash() {
  visible = false
  wait(0.25)
  visible = true
}

fn patrol() {
  while true {
    move_to(point_a)
    wait(2.0)
    move_to(point_b)
    wait(2.0)
  }
}

EXPLANATION: In the flash function, execution yields for 0.25s between property changes. In patrol, the while loop remains active even though the function yields for 2 seconds at each point, preserving its position in the loop.

COMMON NOTES / LIMITATIONS

Wait times are frame-accurate based on engine delta time.

Fibers are lightweight and managed by the engine's VM.

You can yield from inside nested function calls; the entire stack will wait and resume.
