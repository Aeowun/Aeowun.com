FIRST SCRIPT

Learn how to create an .aeo file, attach it to a voxel block, and log diagnostic output on initialization.

GOAL

This tutorial will guide you through creating your very first standalone AeoScript source file, attaching it to an authored voxel block using the editor layout tools, and intercepting the game lifecycle initialization sequence to print output messages.

PREREQUISITES

  • — AeoScript Overview — Core paradigms of the language.
  • — Tutorial 1: First World — Basic scene management and workspace handling.

WHAT YOU WILL BUILD

You will write an init_test.aeo script file, bind it to a block instance via the editor properties inspector, and log an authenticated initialization verification signature into the engine console terminal upon simulation startup.

STEP-BY-STEP INSTRUCTIONS

  1. Open Your Existing Project: Open AeoEngine and load the FirstWorld project you created in the previous guide.
  2. Create the Script File: In the editor Asset Browser panel, right-click inside the scripts/ folder, select New File, name it init_test.aeo, and press Enter. Double-click the file to open the internal editor text panel.
  3. Implement the Ready Hook: Type the custom script structure to bind into the initial hook. We will declare an explicit fn on_ready() callback that invokes the logging namespace.
  4. Select an Editor Target: Click the selection arrow tool in the left toolbar, then click on one of the blocks in your 3D floor map to highlight it.
  5. Bind the Script Component: Look at the Properties Panel on the right side of the editor. Find the "Script Binding" field, click the ellipsis (...) button, choose your newly created init_test.aeo from the project assets directory, and hit Apply.
  6. Execute and Monitor Diagnostics: Open the Console pane by clicking View > Panels > Diagnostic Console at the top menu bar. Press F5 to start Play mode. Monitor the terminal panel to locate your logged text output. Click Escape to stop simulation.
INIT_TEST.AEO AEOSCRIPT 
// init_test.aeo - AeoScript lifecycle entry binding test
fn on_ready() {
    debug.log("AeoScript environment successfully initialized on Block handle!")
}

EXPLANATION

In this architecture, AeoScript source text is parsed into an abstract syntax tree and cached by the engine compiler. The fn on_ready() declaration acts as a distinct engine lifecycle callback hook. When the virtual machine instantiates live cells upon entering Play mode, it scans attached script bindings and automatically spawns a dedicated fiber context to execute on_ready() exactly once, allowing you to invoke debug.log() safely.

RESULT

When the environment finishes loading after hitting F5, a glowing cyan line will appear within the Diagnostic Console pane displaying the text message: AeoScript environment successfully initialized on Block handle!
