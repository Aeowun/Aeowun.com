FIRST SCRIPT

Learn how to create an .aeo file, attach it to a voxel block, and log diagnostic output on initialization.

GOAL

This tutorial will guide you through creating your very first standalone AeoScript source file, attaching it to an authored voxel block using the editor layout tools, and intercepting the game lifecycle initialization sequence to print output messages.

PREREQUISITES

  • — AeoScript Overview — Core paradigms of the language.
  • — Tutorial 1: First World — Basic scene management and workspace handling.

WHAT YOU WILL BUILD

You will write an init_test.aeo script file, bind it to a block instance via the editor properties inspector, and log an authenticated initialization verification signature into the engine console terminal upon simulation startup.

STEP-BY-STEP INSTRUCTIONS

  1. Open Your Existing Project: Open AeoEngine and load the FirstWorld project you created in the previous guide.
  2. Create the Script File: Create scripts/init_test.aeo in the Script Workspace.
  3. Implement the Ready Hook: Declare on_ready() inside the entity declaration that matches the selected Cell identity.
  4. Select an Editor Target: Click the selection arrow tool in the left toolbar, then click on one of the blocks in your 3D floor map to highlight it.
  5. Bind the Script: Set the Cell Identity to FirstScriptBlock, then attach init_test.aeo to that Cell in the Properties panel.
  6. Execute and Monitor Diagnostics: Press Play and verify the message in PRINT OUTPUT.
INIT_TEST.AEO AEOSCRIPT 
entity FirstScriptBlock {
    fn on_ready() {
        debug.log("AeoScript initialized on FirstScriptBlock.")
    }
}

EXPLANATION

A lifecycle hook belongs to the matching bound entity declaration. When Play starts, the runtime instantiates that binding and invokes on_ready() for the matching Cell.

RESULT

When the environment finishes loading, PRINT OUTPUT displays: AeoScript initialized on FirstScriptBlock.
