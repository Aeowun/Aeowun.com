RUNTIME CELL

Learn how to instantiate new voxel cells dynamically during simulation using the built-in cell namespace.

GOAL

This tutorial will guide you through instantiating fresh voxel assets programmatically during simulation via script handles, rather than authoring them manually ahead of time inside the editor grid layout.

PREREQUISITES

  • — API Reference Hub — Specifications regarding Cell Handles and runtime allocation.
  • — Authored vs Runtime State — Understanding how the engine manages data.
  • — Tutorial 3: Interactive Object — Deep understanding of asynchronous event behaviors.

WHAT YOU WILL BUILD

You will write a dynamic spawning script file that programmatically allocates a glowing green block at a designated 3D coordinate vector exactly when the user clicks Play mode.

STEP-BY-STEP INSTRUCTIONS

  1. Create the Spawning Script File: In your Asset Browser pane, create a new asset file inside the scripts/ directory named spawner.aeo.
  2. Intercept the Initialization Callback: Open the text area for spawner.aeo and write the structural fn on_ready() method wrapper block.
  3. Allocate a Fresh Object Instance: Invoke the built-in system namespace creation constructor by writing const spawned_block = cell.new("Block").
  4. Define Spatial and Aesthetic Properties: Position your new element by declaring a three-element spatial vector: spawned_block.position = [5, 3, 5]. Paint it bright green using an RGB color array: spawned_block.color = [0, 1, 0].
  5. Attach to a Core Anchor: Select any static block within your viewport area, slide into the properties sheet on the right, and link the script binding slot to spawner.aeo.
  6. Run and Confirm Allocation: Trigger live simulation with F5. Look closely at coordinate position [5, 3, 5]. A brand new lime green block has appeared that did not exist in your editor layout sheet. Click Escape to stop play testing.
SPAWNER.AEO AEOSCRIPT 
// spawner.aeo - Programmatic runtime cell instantiation
fn on_ready() {
    // Instantiate a volatile play-mode-only block
    const spawned_block = cell.new("Block")

    // Configure runtime parameters
    spawned_block.position = [5, 3, 5]
    spawned_block.color = [0, 1, 0]
}

EXPLANATION

AeoEngine splits memory layout data into Authored State and Runtime State. Built-in elements added via the editor palette are baked directly into your permanent project save data on disk. Conversely, calling cell.new("Block") instructs the memory manager to allocate a dynamic, volatile cell container within the active play session cache. These objects are never serialized to your source files and vanish cleanly without leaving loose references when you exit simulation mode.

RESULT

Upon clicking Play, a completely new green voxel block generates automatically at coordinate location [5, 3, 5], floating precisely according to your vector overrides.
